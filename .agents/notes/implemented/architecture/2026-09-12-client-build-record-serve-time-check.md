# Agent Note: Serve-time client build record check

Status: implemented

English | [中文](2026-09-12-client-build-record-serve-time-check.zh.md)

## Problem

The client build record `.dsh-build/client-build-environment.json` binds the public client build environment to the exact artifacts a complete root build produced. Its verifier ran only in release tooling and end-to-end tests, so a partial rebuild — `pnpm --filter @deepseek-ai/dsh-web-frontend build`, or any tsdown client-bundle rebuild — rewrote served artifacts while the record still described the previous build. The SPA server read files per request with no record consultation: the browser kept running code from an unknown build with no error anywhere, and the divergence surfaced only when a human compared commit stamps by hand.

## Decision

The record module lives in `@deepseek-ai/dsh-host-frontend-static` (`src/client-build-record.ts`): the SPA dist server owns the consistency contract of the frontend it serves, and build orchestration plus release tooling write and verify through that module. A package's `src` cannot import repository `scripts/` under its `rootDir`, while `scripts/` may import package `src` — `scripts/client-build-environment.ts` re-exports the record API so its build-time consumers keep one import path, and `tsconfig.client.json` lists the record module because it includes the scripts module in its program.

The record format is version 2 and adds a `dist` digest computed over the frontend dist directory with dist-root-relative paths, beside the complete artifact digest. A server can therefore recompute the digest from the directory it serves without knowing the repository layout.

At activation `frontend-static` verifies the dist against the record found by walking up from the dist root. A dist-mismatch or an unreadable record logs an actionable `console.error` naming the record, the recorded commit, and both remedies — `pnpm run build` for the complete build that refreshes the record, `pnpm run dev:web` for the watch loop. A dist with no ancestor record stays silent, so custom and preview deployments boot unchanged, and the check never blocks serving. `dev-web` prints that the record refreshes only on a complete build, so the watch loop's expected divergence is named at its source.

## Alternatives considered

**The package imports `scripts/client-build-environment.ts`.** The package tsconfig's `rootDir: src` rejects files outside `src` (TS6059), and bundling repository scripts into the package runtime would break the artifact plane for published installs.

**The composer passes the record path as plugin config.** `dsh-web-app` is the only mounter and resolves `distIndex` itself; an optional config field would default-disable the check in exactly the shipped composition where the silent-stale-code failure occurs, and the dist-relative record discovery needs no new configuration surface.

**Detect commit-stamp drift against Git instead of digesting the dist.** The commit stamp describes which sources were built, not what is on disk; a rebuilt dist with a stale record — the failure this check targets — is invisible to a stamp comparison, and a dirty worktree makes HEAD comparisons unreliable.

**Verify on every index request.** Digesting the dist per request multiplies a whole-directory walk by page loads to catch a divergence that activation already reports; artifacts rewritten while a server runs are the dev loop's contract, not an inconsistency.

## Consequences

The check covers the served dist only: a loader-delivered `lib/client.js` rebuilt without the dist still matches the record's `dist` digest, and that staleness surfaces only through the complete artifact digest verified by release tooling and a complete `pnpm run build`. Server boots during `dev:web` print the mismatch warning even though the divergence is intentional; the dev-loop note in `dev-web` explains why the record stays stale. A format-1 record fails verification with the rebuild remedy, so records written before this change are regenerated by the next complete build rather than trusted.
